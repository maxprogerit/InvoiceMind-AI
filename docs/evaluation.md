# Evaluation

> **Status (2026-11-27): the 32-document set has not been run against the real model yet.** This environment has no
> OpenAI key, and this file is only ever written by `eval/run_eval.py` after a real run, so there are no current
> numbers here to quote. Run it once (below) and this page is replaced by the measured report.

## What the run measures

`eval/run_eval.py` sends every document through `app/pipeline.py`, the code behind `POST /invoices` (PDF text layer
or Tesseract OCR, the model with grounding and injection detection, then the deterministic validation), and compares
the result with the ground truth. The report it writes contains:

| Metric | Definition (code: `extract-service/evaluation/metrics.py`, tests: `tests/test_eval_metrics.py`) |
|---|---|
| Per-field accuracy | vendor, invoice number, date, currency, subtotal, tax, total, line items: share of documents with the value equal to the ground truth (money to the cent, text ignoring case/spaces/punctuation, line items exact when every printed row is found and nothing is added) |
| Auto-validated vs needs review | auto-validated = none of the backend's review triggers fired (validation not `valid`, the model asked for review, suspected prompt injection, confidence < 0.6 on vendor/number/date/total) |
| False "valid" | auto-validated although at least one value is wrong: the errors that would reach approval unseen |
| Latency, cost | average wall time per invoice (OCR + model + validation) and the model alone; average and total cost from the token counts and the configured prices |
| Date and model | in the report header, with the reasoning effort and OCR languages |

## Running it

```bash
# .env: OPENAI_API_KEY, OPENAI_MODEL, and the model's real prices (USD per 1M tokens), e.g.
#   OPENAI_PRICE_INPUT_PER_1M=...  OPENAI_PRICE_OUTPUT_PER_1M=...
EVAL_MAX_COST_USD=1.00 docker compose --profile eval run --rm eval
```

* **Spend cap:** `EVAL_MAX_COST_USD` (default 2.00). Before each document the script estimates its cost from the
  average so far and stops when the next one would cross the cap; the report then says how many documents were not
  run. Without the two price variables every cost reads 0 and the cap could not work, so the script refuses to start.
* `--only 19,24` runs a subset; `EVAL_EXTRACTOR=rules` checks the script itself with the rule-based test double
  (no key, no cost) and writes `eval/results/smoke-test.*` only, never this page.
* Full per-document output, including predicted values: `eval/results/latest.json`.

## The evaluation set

32 **synthetic** invoices in `samples/invoices/`, ground truth in `samples/ground_truth/` (what is printed on the
page; money as decimal strings). They are generated by `samples/generate.py`, carry a footer *"Synthetic test
document … Not a real invoice."* and `"synthetic": true` in their ground truth.

| Tag | Documents | Examples |
|---|---|---|
| text-pdf | 22 | classic, modern, German and Russian layouts; EUR, USD, GBP, CHF, RUB, SEK |
| scan (PNG/JPG or scanned PDF) | 10 | rotation up to 2.6°, noise, blur; `27` is a 2-page PDF without a text layer |
| multi-page | 4 | `11` (filler rows), `25` (46 items), `26` (34 items, two VAT rates), `27` (scanned) |
| multi-tax | 6 | 19 % + 7 % (DE), 20 % + 0 % (UK), 25 % + 12 % (SE), one scanned, one with a discount row |
| discount | 4 | discount as a negative line (`22`, `23`, `30`); discount only in the totals block (`24`) |
| decimal comma | 12 | `1.234,56` and `1 234,56` |
| credit note | 2 | one printed with minus signs, one with positive amounts |
| prompt injection | 1 | hidden text telling the model to change the total and vendor |

`24-discount-totals` is expected to go to review even when read perfectly: its line items do not add up to the
subtotal and the schema has no discount field, so the arithmetic cannot be confirmed by code.

**Real invoices** (redacted) go to `samples/real/` with the same layout; the report lists them separately. See
[`samples/real/README.md`](../samples/real/README.md).

**Limits:** synthetic documents are cleaner than real mail, and 32 documents give indicative percentages, not an
SLA. One run per model; repeat runs vary slightly.

## Previous run (history, different pipeline)

On 2026-10-15 the earlier ai-service (before the merge; extraction without the deterministic validation step) was
run on the first 18 of these documents with `gpt-5.5`, reasoning effort `none`: 18 of 18 extracted completely
correctly (all header fields and 70 of 70 line items), two correct documents flagged for review, 22,480 input and
4,185 output tokens. Raw output: `eval/results/2026-10-15-ai-service-18-docs.json`. Those documents have since been
re-rendered with a "synthetic" footer and corrected VAT labels (for example `8.1%` instead of `8%`), and the
metrics are defined differently, so the numbers are not comparable with a new run.
